# 党建云平台前端

党员发展全过程管理系统的 Vue 3 + TypeScript + Element Plus + Vite 单页应用。

目前处于前后端联调阶段。认证、超级管理员成员与支部维护、资讯公告读写、活动基础管理与活动参与名单查询、角色管理、日志查询及本人资料查询已接入接口；党员发展、我的培养、支部成员工作台、统计和资源中心的当前路由仍为占位页。后端已有更多业务接口，尚未等同于前端功能可用。

详细模块状态、后端新增契约、Issue 缺口与联调限制见[前后端接入现状](docs/前后端接入现状.md)。该文档按代码核对，不代表部署或生产验收。

## 开发与检查

使用 npm 和提交的 `package-lock.json`。CI 使用 Node.js 20；本地还应满足锁定 Vite 版本的 Node.js 引擎要求。

```bash
npm ci
npm run dev
```

开发地址默认是 `http://localhost:5173`。API 前缀由 `VITE_API_BASE_URL` 配置，请求模块中的路径不重复包含 `/api`。开发代理见 `vite.config.ts` 的 `server.proxy`；按实际联调环境配置目标地址，勿将凭据提交到仓库。

| 命令                                | 用途                       |
| ----------------------------------- | -------------------------- |
| `npm run dev`                       | 启动开发服务器             |
| `npm run build`                     | 生产构建至 `dist/`         |
| `npm run preview`                   | 预览生产构建               |
| `npm run typecheck`                 | Vue 与 TypeScript 类型检查 |
| `npm run check:permissions`         | 权限矩阵及开发预览策略检查 |
| `npx eslint src --ext .vue,.ts,.js` | 只读 ESLint 检查           |
| `npm run lint`                      | ESLint 检查并自动修复      |
| `npm run format:check`              | 检查 `src` 格式            |
| `npm run format`                    | 格式化 `src`               |

项目没有配置通用单元测试或端到端测试框架；`check:permissions` 是独立的断言脚本，不能替代业务联调。

现有浏览器回归脚本都使用 Node.js 测试运行器和仅开发依赖 `playwright-core`。首次运行先安装浏览器：

```bash

npm run test:branches
npm run test:activity-participation
npm run test:member-import
npm run test:members
npm run test:system
```

也可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定已有 Chromium 的绝对路径。各脚本各自启动本地 Vite、在独立浏览器上下文中拦截业务接口，不连接真实后端。

- `test:branches`：支部表单回归，验证正常 401 刷新、搜索清空竞态、详情切换和退出/换号隔离。
- `test:activity-participation`：21 项活动参与管理回归，验证权限预检失败即停止名单与导出、分页 total 取自分页响应、成员编号合法性与筛选回第一页、页签懒加载、未知签到类型兜底、导出不带筛选参数且错误内容不存为 xlsx、防重复导出、换号后的旧响应隔离、活动 A/B/A 切换、筛选请求交错、换号/活动切换/退出/卸载后的旧下载隔离，以及正常 401 刷新重放时保留筛选、分页与会话身份；另覆盖非管理角色不请求、活动详情页入口可见性、非法编号与窄屏不溢出。
- `test:member-import`：成员 Excel 导入回归，验证填写规则与真实支部核对、支部选项加载/为空/失败重试、文件校验、四种结果分类、4xx 确定性拒绝与 5xx 结果未知的区分、防重复提交、上传后等待、回读失败保留报告、CSV 行号与转义、关闭重开与换号/退出隔离、正常 401 刷新重放、重置筛选无写请求、非超管不可导入。
- `test:members`：成员新增/更新白名单、关联保留与替换、政治身份分页字典与独立筛选、导出范围与 Blob 错误、批量启停/调整支部/部分成功/异常结果/超时、会话隔离、登录角色链路及窄屏键盘操作。

各脚本的 HTTP 拦截只证明前端交互与反馈语义，不代表真实 Excel 内容、后端持久化或生产验收。CI 会安装 Chromium 并运行这些回归脚本，任一失败都会阻止 `build`；成员管理作业同时检查权限，活动参与作业同时检查新增脚本与 CI 格式。

## 角色、会话与权限

角色定义和页面权限矩阵位于 `src/config/permissions.ts`，路由守卫位于 `src/router/index.ts`。服务端仍负责最终鉴权及数据范围。

| 后端登录角色   | 前端角色          | 含义                                             |
| -------------- | ----------------- | ------------------------------------------------ |
| `super_admin`  | `super_admin`     | 超级管理员                                       |
| `branch_admin` | `party_secretary` | 支部管理员；界面目前标为“党支部书记”             |
| `student`      | `party_member`    | 普通成员；界面目前标为“普通党员”，不代表政治身份 |
| 未知编码       | `party_member`    | 回退为最低权限角色                               |

`activist` 仅保留用于开发预览和旧 Mock 兼容。政治身份与系统角色分别建模，不能从前端角色名称推断成员的真实发展阶段。

只有开发环境启用 `VITE_SKIP_LOGIN=true` 且当前无 access token 时，才允许免登录预览和角色切换。预览不会获得服务端授权，真实请求仍可能返回 401；生产环境不启用该开关。

## 请求与数据

`src/api/request.ts` 使用 Axios，普通 JSON 业务响应按 `{ code, message, data }` 解包；文件下载使用 Blob。自动携带 Bearer token，普通业务请求遇到 401 时尝试刷新并重放一次，失败则清理会话并跳转登录页。

支部页面另用会话身份标记隔离退出或换号前的旧响应；该标记在正常令牌刷新时保持不变，避免丢失未保存表单。请求层的 Token 快照与刷新校验仍独立保留。

- `auth.ts`：账号密码、邮箱验证码、刷新与退出；手机号虽有封装，页面没有入口，后端短信真实发送仍缺。后端 CAS 端点已有，前端尚未接入。
- `members.ts`、`branches.ts`：当前仅接超管接口；支部表单按角色字典定位 `branch_admin` 并分页查询书记候选，提交真实用户 ID，创建强制 `status=1`、编辑不改状态；成员导入错误可下载 CSV，尚无成员数据导出或支部 Excel 导入入口。
- `content.ts`、`admin-content.ts`：已发布资讯查询与超管内容管理。正文通过纯文本插值展示，未直接渲染接口 HTML。
- `activities.ts`：已发布活动查询、活动类型及超管 CRUD/状态管理。
- `activity-participation.ts`：管理侧报名/签到分页与签到名单导出，全部走 `v4/activities/{id}` 范围端点，数据范围由后端守卫判定。
- `roles.ts`、`logs.ts`：角色维护与日志分页查询；任意新建后端角色不会自动变成前端业务菜单。
- `profile.ts`：当前用户本人资料查询。

首页资讯使用真实接口，Store 中仍保留旧新闻、通知等 Mock。统计、轮播、快捷入口和旧原型数据不能作为真实业务结果。

### 支部书记与状态约定

支部维护表单按当前服务端契约要求书记必填：先从角色字典取得 `branch_admin` 的真实角色 ID，再按该角色分页查询成员，提交用户 ID；编辑时会单独回显不在当前候选页中的书记。支部状态是 `1` 正常、`0` 已删除（软删除），不适用成员表的 `1` 启用 / `2` 停用规则，表单不提供停用切换。#29 早期评论提出「允许先创建未指定书记的支部」，但后续服务端规则已要求 `secretary_id` 非空且该用户持有 `branch_admin`；本次按服务端规则实现，是否重新支持空书记属于业务决策，未在前端放开。支部 Excel 模板下载与导入仍未接入。该书记链路已在本机真实后端完成新增、编辑、回读与非支委拒绝路径的联调，证据边界见[前后端接入现状](docs/前后端接入现状.md)。

### 成员 Excel 导入约定

成员导入弹窗在提交前说明填写规则（先维护支部、按正常支部全名匹配、所属支部可留空、重复账号/学号/手机号/邮箱按行失败且不覆盖、部分成功后重传整个文件会产生重复失败），并单独加载正常支部选项供核对，支持手动刷新与本地名称筛选。

- 支部选项使用导入专属状态，不依赖角色字典；加载失败只提示「暂时无法核对」并提供重试，不显示为「没有支部」，也不新增禁止导入的业务规则；所属支部为空的行仍可提交，最终由服务端裁决。
- 结果按服务端计数分为全成功、部分成功、全部失败和无数据四类，全部失败不再弹成功提示；请求失败或超时不伪造计数、不自动重传，超时文案只说明结果未确认并引导核对列表。
- 服务端失败按两种语义区分：HTTP 4xx 表示服务端已明确拒绝（如「Excel 中没有可导入的数据行」），界面说明「导入未执行」并转达原因；5xx、超时与断网可能发生在写入过程中，只说结果未确认，不声称未写入。
- `row` 是 Excel 行号，界面与 CSV 报告都按服务端原值展示，不按数组下标重排。
- 成功行会回到第一页回读列表并保留已应用筛选；回读失败只提示列表问题，不篡改已获得的导入报告。
- 导入弹窗用自己的请求序号与会话身份快照隔离关闭重开、换号、退出和过期响应；正常 401 刷新保留文件与本次结果，由请求层重放。
- 列表「重置筛选」只清空筛选条件并重新查询，不删除成员或撤销导入。

成员编辑现已将姓名、学号、学院、班级设为只读，更新仅提交可编辑白名单；编辑支部/角色只能保留或有效替换，不提供接口不支持的解除关联。列表和详情区分未分配支部与名称不可用，政治身份独立于登录角色展示。

成员查询分为普通管理查询与政治身份查询：普通查询保留关键词或支部单独查询及全部状态，因后端缺陷不允许关键词与支部组合；身份查询仅支持身份与明确的启用/停用状态，不允许关键词/支部组合。切换会提示并清理条件。导出只在身份模式可用，使用已应用条件导出全部匹配记录，不是当前页；管理模式不会静默删除不支持的条件执行导出。

批量启用、停用和调整支部使用真实批量端点，限定当前页去重后 1–200 人，确认后提交，按成员 ID 展示部分成功与逐项失败，回读失败保留结果。超时/断网不自动重传。新增能力均做会话与过期响应隔离。

### 活动参与管理约定

`/activity/:id/participation` 只对超级管理员与支部书记开放，并由 `activity:manage` 权限与角色列表双重限制；普通成员从活动详情只能看到公开活动信息。页面先调用 `v4/activities/{id}` 做权限预检，成功后才请求报名、签到与导出，预检失败时一律停止后续请求。跨支部与不存在的活动在服务端使用同一提示，前端只转达结论，不推断活动是否存在。

- 报名与签到各自维护独立的分页、筛选和请求序号；成员编号只接受正整数，非法输入不发起请求，筛选变化统一回到第一页，页签懒加载。
- `total` 直接取自对应分页响应，页面不用当前页行数或签到记录推算缺席、迟到和出勤率。
- 导出按钮固定请求本活动的完整名单，不携带 `userId`、`page`、`size`；返回内容先校验 xlsx 文件头（ZIP），非 xlsx 时尝试转达服务端错误原因且绝不保存为表格。
- 账号切换、角色变化、活动编号变化和页面离开都会使在途请求与下载失效，旧响应不写回新会话。

#19 本机真实联调 27/27 通过，覆盖当前超管登录、编辑回读、真实 xlsx、批量持久化及导入。后端两类组合查询范围缺陷也已实测复现，因此仍不具备关闭条件；当前本机账号正常不代表历史响应来源或生产环境已恢复。详见 [Issue #19 验收记录](docs/Issue-19-验收记录.md)。支部 Excel 导入仍属 #22/#29，不在本次范围。

## 架构与文件入口

- `src/App.vue`：顶部用户栏、左侧 `SideNav`、业务页面、页脚和悬浮助手；登录页独立布局。移动端侧栏在 680px 断点切换为抽屉。
- `src/stores/app.ts`：导航、当前角色、布局状态和部分 Mock；会话状态由 `src/utils/session.ts` 管理。
- `src/router/index.ts`：页面清单、登录与角色门禁、导航高亮。新增导航时同步 Store 的菜单和守卫的 `pathKeyMap`。
- `src/views/content/`：当前资讯阅读及管理页面；旧新闻、公告列表和 `ContentDetail.vue` 已不由当前资讯路由使用。
- `src/views/WorkspacePlaceholder.vue`：未接入模块的实际入口；保留的党员发展、资源和统计原型不是当前业务入口。
- `src/main.ts`：全局注册 Element Plus 及图标。Vue API 仍需显式导入，`ElMessage`、`ElMessageBox` 等命令式 API 也需显式导入。
- `src/styles/global.scss`：主题与公共布局；优先使用 CSS 变量。Vite 注入 SCSS 主题变量，`@` 映射到 `src`。

## CI 与交付

`.github/workflows/ci.yml` 对 `main`、`feature/**`、`fix/**` 的 push，以及面向 `main` 的 PR 执行格式、ESLint、类型检查、支部表单回归、活动参与管理回归、成员导入回归、成员管理回归、系统管理回归和构建；各浏览器回归均为 `build` 的前置检查。成员管理作业包含 `check:permissions`。

工作流对同仓库非草稿 PR 配置了检查通过后请求 Auto-merge；实际合并还受仓库设置和分支保护约束。创建 PR 前需留意这一自动行为。`main` push 构建上传 Pages 产物，工作流本身没有部署步骤。
