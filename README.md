# 党建云平台前端

党员发展全过程管理系统的 Vue 3 + TypeScript + Element Plus + Vite 单页应用。

目前处于前后端联调阶段。认证、超级管理员成员与支部维护、支委成员工作台、资讯公告读写、活动基础管理与活动参与名单查询、角色管理、日志查询、本人资料查询、本人电子培养档案（我的培养）、管理侧成员培养档案（党员发展，只读 + 政治身份变更发起）与身份变更审批、及数据统计（政治身份分布 + 管理待办计数 + 本人学习汇总）已接入接口；资源中心的当前路由仍为占位页，管理侧批量身份调整因后端无端点已移除路由。后端已有更多业务接口，尚未等同于前端功能可用。

详细模块状态、后端新增契约、Issue 缺口与联调限制见[前后端接入现状](docs/前后端接入现状.md)。该文档按代码核对，不代表部署或生产验收。

## 开发与检查

使用 npm 和提交的 `package-lock.json`。CI 使用 Node.js 20；本地还应满足锁定 Vite 版本的 Node.js 引擎要求。

```bash
npm ci
npm run dev
```

开发地址默认是 `http://localhost:5173`。API 前缀由 `VITE_API_BASE_URL` 配置，请求模块中的路径不重复包含 `/api`。开发代理见 `vite.config.ts` 的 `server.proxy`；按实际联调环境配置目标地址，勿将凭据提交到仓库。

| 命令                                | 用途                         |
| ----------------------------------- | ---------------------------- |
| `npm run dev`                       | 启动开发服务器               |
| `npm run build`                     | 生产构建至 `dist/`           |
| `npm run preview`                   | 预览生产构建                 |
| `npm run typecheck`                 | Vue 与 TypeScript 类型检查   |
| `npm run check:permissions`         | 权限矩阵及开发预览策略检查   |
| `npx eslint src --ext .vue,.ts,.js` | 只读 ESLint 检查             |
| `npm run lint`                      | ESLint 检查并自动修复        |
| `npm run format:check`              | 检查 `src` 格式              |
| `npm run format`                    | 格式化 `src`                 |
| `npm run test:identity-change`      | 身份变更发起与审批浏览器回归 |

项目没有配置通用单元测试或端到端测试框架；`check:permissions` 是独立的断言脚本，不能替代业务联调。

| 未知编码       | `party_member`    | 回退为最低权限角色                               |

`activist` 仅保留用于开发预览和旧 Mock 兼容。政治身份与系统角色分别建模，不能从前端角色名称推断成员的真实发展阶段。

只有开发环境启用 `VITE_SKIP_LOGIN=true` 且当前无 access token 时，才允许免登录预览和角色切换。预览不会获得服务端授权，真实请求仍可能返回 401；生产环境不启用该开关。

## 请求与数据

`src/api/request.ts` 使用 Axios，普通 JSON 业务响应按 `{ code, message, data }` 解包；文件下载使用 Blob。自动携带 Bearer token，普通业务请求遇到 401 时尝试刷新并重放一次，失败则清理会话并跳转登录页。

支部页面另用会话身份标记隔离退出或换号前的旧响应；该标记在正常令牌刷新时保持不变，避免丢失未保存表单。请求层的 Token 快照与刷新校验仍独立保留。

- `auth.ts`：账号密码、邮箱验证码、刷新与退出；手机号虽有封装，页面没有入口，后端短信真实发送仍缺。后端 CAS 端点已有，前端尚未接入。
- `members.ts`、`branches.ts`：`members.ts` 同时封装超管接口与支委范围接口（`/v4/members/page`、`/{id}`、`/{id}/contact`、`/export`，成员名单导出已由 `/members` 与 `/members/branch` 接入），`branches.ts` 接超管支部接口（含模板下载与 Excel 导入，导入结果复用 `members.ts` 的 `ImportResult` 类型）；支部表单按角色字典定位 `branch_admin` 并分页查询书记候选，提交真实用户 ID，创建强制 `status=1`、编辑不改状态；成员导入错误可下载 CSV，支部导入同样支持逐行结果与错误报告 CSV。
- `content.ts`、`admin-content.ts`：已发布资讯查询与超管内容管理。正文通过纯文本插值展示，未直接渲染接口 HTML。
- `activities.ts`：已发布活动查询、活动类型及超管 CRUD/状态管理。
- `activity-participation.ts`：管理侧报名/签到分页与签到名单导出，全部走 `v4/activities/{id}` 范围端点，数据范围由后端守卫判定。
- `roles.ts`、`logs.ts`：角色维护与日志分页查询；任意新建后端角色不会自动变成前端业务菜单。
- `profile.ts`：当前用户本人资料查询与联系方式更新（`PUT /v4/user/profile` 只提交实际变化字段；后端为部分更新且空串无法清空，因此界面不提供清空操作）。
- `cultivation-profiles.ts`：电子培养档案前端契约（`CultivationProfile` 及全部分区块类型）。本人完整培养档案聚合只封装 `/v4/cultivation-profiles/me`，不接受用户标识参数；记录内的活动、课程、人员关联只有编号，页面按编号展示，不为补名额外请求接口。
- `cultivation.ts`：管理侧档案端点 `GET /v4/cultivation-profiles/{userId}`，类型复用 `cultivation-profiles.ts`；范围由服务端裁决，不带任何范围参数，非法编号在提交前即拒绝。
- `branch-members` 相关 API 复用在 `members.ts`：支委工作台只调用 scoped 端点，超管专属的 `/v4/admin/**` 不在其调用链中。
- `statistics.ts`：政治身份分布（`/v4/statistics/distribution`）、管理待办（`/v4/statistics/dashboard`）与本人学习汇总（`/v4/user/study-records/mine/summary`）。三个端点都不传任何范围参数；`parseDistribution` / `parseDashboard` / `parseStudySummary` 校验计数为非负安全整数，结构非法时按失败处理而不补 0，`avgScore` 为 `null` 时保留 `null`（表示无记录）而不是归为 0。

### 支部书记与状态约定

### 支部 Excel 导入约定

`/branches` 的「下载模板」直接取后端生成的 xlsx（`GET /v4/admin/branches/template`，文件名「党支部导入模板.xlsx」），「导入支部」上传后调 `POST /v4/admin/branches/import`（`multipart/form-data`，字段名 `file`）。模板固定 4 列：支部名称、所属学院、简介、书记用户id（填 `tb_user.id`）。

- 模板响应先校验 ZIP 文件头；JSON 错误响应由请求层提示，`200 + text/html` 之类网关错误页由文件头校验拦下，两种情况都不会把错误内容存成 xlsx。
- 导入结果与成员导入同构（后端同一个 `ImportResult` DTO）：共 X 行、成功 Y 行、失败 Z 行，`errors[].row` 是 Excel 实际行号（表头第 1 行，数据从第 2 行开始），界面与 CSV 报告都按原值展示，不按数组下标重排。
- `total` 为 0（只有表头）显示「文件中没有数据行」，不显示为全部成功。
- 导入**不校验**书记是否持有 `branch_admin` 角色（后端 `importBranches` 只校验非空），手工新增/编辑才校验。前端不额外加严，弹窗内已写明这条差异，避免出现「导入成功但编辑报错」的困惑。
- 支部名称与任意状态（含软删除）的现有支部重名即该行失败；单行失败不影响其他行；导入的支部状态一律为 `1`。
- 前端只做文件级校验（只接受 `.xlsx`、非空、≤10 MB），不做客户端解析或行内容预判，服务端是唯一判定者。
- 提交按钮在 handler 入口**同步**置 `importing`，同一事件循环内连点也只发出一次请求；失败时保留已选文件，可修正后重新上传。
- 导入成功且 `successCount > 0` 时自动重新拉取当前分页列表；分页越界沿用页面既有 `loadBranches()` 行为，不另加分页修正。
- 导入弹窗用独立的 `importEpoch` 加 `captureSessionIdentity()` 隔离关闭重开、换号、退出与卸载后的迟到响应，`finally` 同样校验会话。
- 跨页同步无需额外机制：`/members` 每次进入都会重新拉取支部选项，导入成功后新支部天然出现在成员导入的支部下拉与筛选中。

支部导入的浏览器回归（`npm run test:branch-import`）只证明前端交互与反馈语义。另在本机真实后端做过一轮联调（35 项断言全通过，脚本在仓库外 `E:/党建云平台/verify/branch-import-live.mjs`）：真实模板字节与 4 列表头、全部成功/部分成功/全部失败/只有表头四类真实响应与 Excel 行号、真实 CSV 内容的行号与原因、导入后列表自动刷新与 `/members` 支部核对列表跨页同步、以及「书记非支委仍可导入」的契约差异均已核实；测试数据带 `BIMP` 前缀并已软删除，残留启用 0。这仍是本机联调，不是 CI/预发/生产验收。

### 成员 Excel 导入约定

成员导入弹窗在提交前说明填写规则（先维护支部、按正常支部全名匹配、所属支部可留空、重复账号/学号/手机号/邮箱按行失败且不覆盖、部分成功后重传整个文件会产生重复失败），并单独加载正常支部选项供核对，支持手动刷新与本地名称筛选。

- 支部选项使用导入专属状态，不依赖角色字典；加载失败只提示「暂时无法核对」并提供重试，不显示为「没有支部」，也不新增禁止导入的业务规则；所属支部为空的行仍可提交，最终由服务端裁决。
- 结果按服务端计数分为全成功、部分成功、全部失败和无数据四类，全部失败不再弹成功提示；请求失败或超时不伪造计数、不自动重传，超时文案只说明结果未确认并引导核对列表。
- 服务端失败按两种语义区分：HTTP 4xx 表示服务端已明确拒绝（如「Excel 中没有可导入的数据行」），界面说明「导入未执行」并转达原因；5xx、超时与断网可能发生在写入过程中，只说结果未确认，不声称未写入。
- `row` 是 Excel 行号，界面与 CSV 报告都按服务端原值展示，不按数组下标重排。
- 成功行会回到第一页回读列表并保留已应用筛选；回读失败只提示列表问题，不篡改已获得的导入报告。
- 导入弹窗用自己的请求序号与会话身份快照隔离关闭重开、换号、退出和过期响应；正常 401 刷新保留文件与本次结果，由请求层重放。
- 列表「重置筛选」只清空筛选条件并重新查询，不删除成员或撤销导入。

成员编辑现已将姓名、学号、学院、班级设为只读，更新仅提交可编辑白名单；编辑支部/角色只能保留或有效替换，不提供接口不支持的解除关联。列表和详情区分未分配支部与名称不可用，政治身份独立于登录角色展示。

成员查询分为普通管理查询与政治身份查询：普通查询保留关键词或支部单独查询及全部状态，因后端缺陷不允许关键词与支部组合；身份查询仅支持身份与明确的启用/停用状态，不允许关键词/支部组合。切换会提示并清理条件。导出只在身份模式可用，使用已应用条件导出全部匹配记录，不是当前页；管理模式不会静默删除不支持的条件执行导出。

批量启用、停用和调整支部使用真实批量端点，限定当前页去重后 1–200 人，确认后提交，按成员 ID 展示部分成功与逐项失败，回读失败保留结果。超时/断网不自动重传。新增能力均做会话与过期响应隔离。

### 支委成员工作台（本支部成员）约定

`/members/branch` 只对支部书记（前端角色 `party_secretary`，后端编码 `branch_admin`）开放，路由 `meta` 保持 `member:manage` 与 `roles: ["party_secretary"]`。页面只用四个 scoped 端点 `GET /v4/members/page`、`GET /v4/members/{id}`、`PUT /v4/members/{id}/contact`、`GET /v4/members/export`，另加一个只读身份字典 `GET /v2/content/identities/page`；不调用任何 `/v4/admin/**` 接口，也不发送 `branchId`——范围由服务端按登录身份限定，前端传范围参数等于尝试扩权。

- `ScopedMemberServiceImpl.buildVos` 只写入 `branchId` 与 `identityId`，不查支部表与身份表，因此列表与详情中的 `branchName`、`identityName` **恒为 null**。页面降级显示：`branchId` 为空显示“未分配”，有值显示“支部名称不可用（编号 x）”；政治身份用一次性加载的 `/v2/content/identities/page` 字典映射，字典缺失显示“身份 #x”，`identityId` 为空显示“未登记”。不为此额外逐行请求接口。
- `status` 缺省等于“仅启用”（服务端 `eq(status, 1)`）。界面只提供“启用（默认）”与“停用”两项：默认不发送 `status`，选“停用”才显式发送 `status=2`；**不提供“全部状态”**，避免把默认语义固化成客户端假设。
- 筛选只开放关键词与启用/停用。`filterDetailIds` 在关键词命中 `tb_user.username` 形成 ID 集合时，只按支委支部额外校验一次，但**不再叠加** `grade`/`major`/`college`/`identityId` 条件（#19 已知缺陷：用户名命中会绕过多维组合筛选）；因此本页不开放这四项组合筛选。
- `total` 一律取服务端值，不用当前页行数推断；失败时清空列表并提供重试，重试沿用已应用条件而不是回到默认查询。
- 联系方式提交是部分更新：只发送用户实际修改的字段，`null`/省略表示“不动”，**空串表示“清空”**。因此校验必须允许空串（手机号 `^$|^1\d{10}$`、邮箱 ≤25、备注 ≤500），不能用 truthy 判断。无变更不发请求；保存按钮在请求期间禁用，双击只提交一次。
- 保存成功会回读详情；回读失败与保存结果分别提示（“保存成功，但回读失败，请手动刷新”），不把回读失败说成保存失败，也不覆盖用户未提交的输入。
- 导出使用已应用条件（关键词与状态），**不含 `page`/`size`/`branchId`**，导出全部匹配记录而非当前页。返回内容先校验 xlsx 的 ZIP 文件头，非 ZIP 时尝试转达服务端原因并拒绝下载。导出列与后端 `EXPORT_HEADERS` 一致：学号、姓名、手机号、邮箱、学院、年级、专业、班级、备注，**不含政治身份与支部列**。
- 页面用请求序号加 `captureSessionIdentity()` 会话快照隔离换号、退出与卸载后的迟到响应；导出另用操作序号隔离，换号后旧 Blob 不会落盘。
- 权限边界：前端门禁只是体验层，服务端 `BranchScopeService` 才是最终裁决。跨支部详情由服务端按“用户不存在”返回，前端原样转达，不提示“无权限”，也不推断成员是否存在。

上述行为由 30 项拦截型回归锁定，并已完成一轮**本机真实后端联调**（57 项断言通过，脚本在仓库外 `E:/党建云平台/verify/live-branch-members-48.mjs`，详见[前后端接入现状](docs/前后端接入现状.md)）。

真实联调确认的两条后端契约现状：

- `branchName`、`identityName` 在列表与详情中确实恒为 `null`（实测 `branchId` 有值、`branchName` 为 null），页面的降级显示是该契约下的必需行为。
- **`PUT /v4/members/{id}/contact` 的「空串清空」不生效**：服务端 `trimToNull("")` 得到 `null`，而 `userDetailMapper.updateById` 使用 MyBatis-Plus 默认 `NOT_NULL` 更新策略会跳过该列，因此接口返回 200 但库中值不变（实测三字段均未变，非空新值写入正常）。前端已按契约发送空串（这是唯一能表达「清空」的取值）；修复属于后端范围，本任务未修改后端。

已知跨模块缺陷同样适用：后端在未认证/令牌过期时可能返回 403 而非 401，前端只在 401 时刷新令牌，因此真实环境中令牌过期会显示 403 且不触发刷新；回归中的 401 刷新场景仅在拦截层成立。

### 活动参与管理约定

`/activity/:id/participation` 只对超级管理员与支部书记开放，并由 `activity:manage` 权限与角色列表双重限制；普通成员从活动详情只能看到公开活动信息。页面先调用 `v4/activities/{id}` 做权限预检，成功后才请求报名、签到与导出，预检失败时一律停止后续请求。跨支部与不存在的活动在服务端使用同一提示，前端只转达结论，不推断活动是否存在。

- 报名与签到各自维护独立的分页、筛选和请求序号；成员编号只接受正整数，非法输入不发起请求，筛选变化统一回到第一页，页签懒加载。
- `total` 直接取自对应分页响应，页面不用当前页行数或签到记录推算缺席、迟到和出勤率。
- 导出按钮固定请求本活动的完整名单，不携带 `userId`、`page`、`size`；返回内容先校验 xlsx 文件头（ZIP），非 xlsx 时尝试转达服务端错误原因且绝不保存为表格。
- 账号切换、角色变化、活动编号变化和页面离开都会使在途请求与下载失效，旧响应不写回新会话。

### 政治身份变更（发起 + 超管审批）约定

身份的两次流转：支委或超管在 `/development/member/:id` 页头点「发起身份变更」生成待审批单，超级管理员在 `/development/identity-changes` 审批。审批入口在 `/development` 页头链接进入，导航未新增顶级项。

- **身份变更不联动登录角色**（红线）：审批通过只写 `tb_user_detail.identity_id`，`role_id`、菜单与权限矩阵一概不变。前端不得因政治身份变成「正式党员」而修改 `currentRole`、导航或路由权限。
- 发起请求体只有 `userId`、`toIdentity`、`reason`（≤500）；`fromIdentity` 由服务端取当前身份快照，前端不传。目标身份来自身份字典分页拉全（按 `level` 升序），字典失败时禁用提交且不用本地兜底列表。
- 提交成功只提示「等待超级管理员审批」，**不刷新档案、不本地改写身份名**；审批后可点页头「重新读取」回读服务端身份。
- 「目标身份与当前身份相同」「该用户已有待审批的身份变更单」由服务端校验，页面不预判禁用，一律原样展示 400 原文。
- 审批 `POST /v4/identity-changes/{id}/review` 仅超管；支委可进页面但无通过/驳回按钮。`managed/page` 对支委**忽略** `status`/`userId`，因此支委视图不发送这两个参数、也不提供对应筛选；超管只支持按成员编号精确过滤，不支持姓名模糊搜索。
- 越权读单与真不存在同为「变更单不存在」，原样转达，不改写成「无权限」。未知状态显示「未知状态（x）」，不与思想汇报的 1/2/3 共用映射。

### 我的培养（本人培养档案）约定

`/my-development` 只对普通成员（`party_member`）与开发预览的 `activist` 开放，路由 meta 保持不变。页面只请求 `GET /v4/cultivation-profiles/me`，由登录态决定查询对象：不接受前端传入的用户标识，带 `?userId=` 也不改变请求目标。

- 当前政治身份取自 `basic.identityName`，未登记时显示“未登记政治身份”，并明确提示“系统角色不代表政治身份”；未分配支部显示“未分配支部”。
- 摘要直接展示服务端 `summary`（思想汇报数/已通过数、签到次数、累计学习分钟数、材料数），前端不重算；`summary` 缺失时显示“暂无统计”而不是用数组长度兜底。活动签到只能描述为“签到次数”，不得与报名次数或参与活动总数混用。
- 七个区块（联系人、身份历史、思想汇报、签到、请假、学习、材料）各自独立空态；分页只在前端已返回的数据上切页，切页不触发请求。
- 档案记录只带外键，显示活动编号或课程编号，不为补名另行请求成员/活动/内容接口；思想汇报正文按纯文本插值。材料 `file:`、汇报附件 `file`、学习记录 `url` 均为服务端内部路径，本页不渲染其值、不生成可点击地址，也不提供下载或上传。
- 未知枚举统一显示“未知状态（x）”，不兜底成通过/已生效/正常；`studyTime` 是 `LocalTime` 学时文本而非时间点，成绩原样展示不转 `Number()`。
- 页面用请求序号加 `captureSessionIdentity()` 会话快照隔离退出、换号与卸载后的旧响应；正常 401 刷新保留页面状态并由请求层重放一次。

### 数据统计（分布 + 管理待办 + 本人学习汇总）约定

`/statistics` 只对超级管理员与支部书记（支委）开放，保留 `statistics:view` 权限。页面三个板块各调一个端点，均不传任何范围参数；范围由服务端按登录身份判定（超管全院、支委本支部，支委无归属支部时服务端返回 400「您尚未归属任何党支部，请联系管理员」）。

- 分布板块：`GET /v4/statistics/distribution`。

- 五个维度（`college`/`major`/`className`/`grade`/`branch`）与后端 `normalizeDimension` 一致。后端 Swagger 控制器注释漏写了 `branch`，但实现已支持；后端对无法识别的维度会静默回退 `college`，因此页面比对 `vo.dimension` 与请求维度，不一致时显式提示实际维度，不把回退结果标成原维度。
- 分组总人数直接取服务端 `total`：它含身份未登记的成员，而身份列只列身份字典，所以各身份人数之和可能小于总人数。页面不修改总人数、不补齐差额、不虚构身份项，也不按固定列序号推断身份。
- 统计未按成员启用/停用过滤，停用成员同样计入，因此总人数不等于“启用成员数”；界面文案已明确这一点。
- 某分组响应中缺少某身份时显示“—”，与人数真实为 0 区分；分组名 `null` 显示“未填写”；不按客户端规则重排分组。
- 页面用请求序号加会话快照隔离维度切换、换号、退出与卸载后的旧响应；切换维度先清空旧结果再请求。
- 管理待办板块：`GET /v4/statistics/dashboard`。两个计数缺失或非法时该板块进错误态而**不补 0**，全 0 显示真实 0；`identityDistribution` 是单一汇总（按身份直接计数、由服务端额外追加未登记行），与分布板块按维度分组的口径不同，页面不合并也不互相换算，两者都未按成员启用/停用过滤。两个计数不可点击（审阅与审批页尚未接入）。
- 本人学习汇总：`GET /v4/user/study-records/mine/summary`。只查当前登录账号本人，`totalMinutes` 按分钟展示并给出「约 X 小时 Y 分钟」，`avgScore` 为 `BigDecimal`、无记录时为 `null`，页面显示「无记录」而不是 0 分；标题已标注「本人数据」，避免被误读为全体成员数据。
- 三个板块各自独立的 loading / error / 重试与请求序号：首屏三个请求一次并行发出、互不阻塞，任一板块失败不影响其它已成功板块，重试只重发自身。

上述口径已由 41 项拦截型回归锁定。另据 PR #69 记录，本轮还跑过一次**本机真实后端联调**（`E:/党建云平台/verify/live-statistics-64*.mjs` 四个脚本）；该轮的断言输出**未落盘保存**，仓库外 `verify/` 下只有脚本与截图 `shots-64-statistics.png`，因此具体数字与结论**不在本仓库内可复核**，仅作为本机过程记录，不构成 CI、预发或生产验收证据。另需注意已知跨模块缺陷：后端在未认证/令牌过期时可能返回 403 而非 401，而前端只在 401 时刷新令牌，因此真实环境下令牌过期会表现为 403 且不触发刷新。该问题已在 Issue #49 评论中向后端提出，未在本任务中修改刷新逻辑。

## 架构与文件入口

- `src/App.vue`：顶部用户栏、左侧 `SideNav`、业务页面、页脚和悬浮助手；登录页独立布局。移动端侧栏在 680px 断点切换为抽屉。
- `src/stores/app.ts`：导航、当前角色、布局状态和部分 Mock；会话状态由 `src/utils/session.ts` 管理。
- `src/router/index.ts`：页面清单、登录与角色门禁、导航高亮。新增导航时同步 Store 的菜单和守卫的 `pathKeyMap`。
- `src/views/content/`：当前资讯阅读及管理页面；旧新闻、公告列表和 `ContentDetail.vue` 已不由当前资讯路由使用。
- `src/views/WorkspacePlaceholder.vue`：未接入模块的实际入口；`/resources` 仍是占位入口（`/development/batch` 已因后端无批量身份调整端点移除路由），`src/views/development/MemberDetail.vue` 与 `statistics.vue` 等原型不是当前业务入口。
- `src/views/statistics/index.vue`：数据统计真实页面；`src/views/statistics.vue` 是未被路由引用的历史 Mock 原型，不作为业务入口。
- `src/main.ts`：全局注册 Element Plus 及图标。Vue API 仍需显式导入，`ElMessage`、`ElMessageBox` 等命令式 API 也需显式导入。
- `src/styles/global.scss`：主题与公共布局；优先使用 CSS 变量。Vite 注入 SCSS 主题变量，`@` 映射到 `src`。

## CI 与交付

`.github/workflows/ci.yml` 对 `main`、`feature/**`、`fix/**` 的 push，以及面向 `main` 的 PR 执行格式、ESLint、类型检查、支部表单回归、支部导入回归、活动参与管理回归、成员导入回归、成员管理回归、支委成员回归、系统管理回归、我的培养回归、党员发展档案回归、身份变更回归、数据统计回归和构建；各浏览器回归均为 `build` 的前置检查。成员管理、支委成员、我的培养、党员发展档案、身份变更、数据统计与支部导入作业包含 `check:permissions`。

工作流对同仓库非草稿 PR 配置了检查通过后请求 Auto-merge；实际合并还受仓库设置和分支保护约束。创建 PR 前需留意这一自动行为。`main` push 构建上传 Pages 产物，工作流本身没有部署步骤。
