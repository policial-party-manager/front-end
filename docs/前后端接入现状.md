## 必须保留的契约边界

- 支部 `tb_branch`：`branch_name varchar(20)`、`college varchar(10)` 均非空，`secretary_id` 非空且外键指向 `tb_user.id`。`saveBranch` 强制 `status=1` 并调用 `requireSecretaryIsBranchAdmin`；`updateBranch` 不使用传入 `status` 修改状态，且仅在 `secretaryId` 非空时校验书记资格；`deleteBranch` 置 `status=0`。支部状态是 1 正常 / 0 已删除，不是成员表的 1 启用 / 2 停用。
- 前端书记候选链路：`GET /api/v4/admin/roles` 取规范化 `roleCode === "branch_admin"` 的动态角色 ID，再按 `roleId` 调 `GET /api/v4/admin/users/page`；提交的是 `UserVo.id`，不是学号、用户名或角色 ID。角色字典缺少该编码时不得退化为全量成员查询；编辑回显当前书记走 `GET /api/v4/admin/users/{id}`，不受候选分页或搜索影响。
- 支部维护页面以独立会话身份标记隔离退出/换号前的响应，正常 401 令牌刷新保留表单；搜索关键词在请求开始时记录，清空会使在途旧搜索失效；详情与书记查询共享详情请求序号，关闭或切换详情后旧响应不回写。仓库内 `npm run test:branches` 用真实页面及模拟 HTTP 响应验证这些交互，并覆盖保存时刷新和跨标签页身份切换；此类回归不是后端持久化或生产验收。
- `openapi.yaml` 中支部请求体的 `status` 描述（0 未删除 / 1 已删除）与 DDL 及服务实现（1 正常 / 0 已删除）相反，字段语义以服务实现和 DDL 为准，不要盲信过时描述（参见 #43 对模板描述漂移的处理）。
- 后端 `importBranches` 只校验「书记用户id」非空并写入 `secretaryId`，未调用 `requireSecretaryIsBranchAdmin`，与手工新增/编辑路径存在资格校验差异；本次前端切片只记录现状，不修改后端。
- `#29` 早期评论要求「允许先创建未指定书记的支部」，与当前服务端非空书记 + 支委角色规则冲突。本次按服务端规则实现，是否重新支持空书记需业务决策；不关闭 #29，不修改数据库约束。
- 系统角色是 `super_admin`、`branch_admin`、`student`；政治身份由字典与当前身份字段表达。后端 `UserVo` 已有 `identityId`、`identityName`，前端成员类型尚未接入。
- 身份变更已有“发起 → 超管审批 → 写回当前身份”的两阶段实现，不能套用旧原型的直接修改身份流程。
- 新支委成员和活动接口使用范围守卫。身份变更服务仍通过 `tb_branch.secretary_id` 查管理支部，与其他新范围接口的所属支部口径不同；接入前需核对，不能假设所有支委端点均已统一。
- 后端 ADR-0001 保留超管 `AdminController` 限制，支委能力主要另设成员/活动入口。控制器及服务实现优先于按 URL 前缀猜测权限。
- 二维码在 Redis 正常路径下默认有效期 60 秒，同一有效码允许多人使用；重复签到由记录约束与业务校验处理，不是一人一码。当前控制器不做地理围栏。`SignQrTokenService` 的进程内降级没有到期清理，且签发响应返回配置时长而非当前码的剩余 TTL；联调须验证这些边界，不能将倒计时展示当成服务端时效已验证。
- 批量错误按业务 ID 定位，Excel 导入错误按行号定位，分别使用 `BatchResult`、`ImportResult`。`ImportResult.errors[].row` 是 Excel 行号（表头为第 1 行），前端必须原样展示与导出，不得按数组下标或分页位置重新编号。
- 成员导入的支部匹配规则（后端 `AdminUserServiceImpl.importUsers` / `importOneUser` 只读核对）：`所属支部` 单元格为空时不做支部校验、允许不分配支部，前端不得擅自改为支部必填；填写了名称时先 trim，再按 `branch_name` 精确匹配 `status=1` 的支部，匹配不到该行报「所属支部不存在（请先维护支部）」。`/api/v4/admin/branches/options` 只返回 `status=1` 的支部，可用于导入前的名称核对，但前端核对不是服务端裁决，也不解析 Excel 内容。
- 成员导入的重复策略：用户名（学号）、学号、手机号、邮箱任一已存在都会按行失败，不覆盖已有成员，也没有跳过/更新/撤销接口。部分成功后重传整个文件时，已成功的行会因重复再次失败。接口注解写「前 6 列必填」，但服务实现只强制学号与姓名为必填、手机号/邮箱格式合法即可，前端不得据注解新增错误规则。
- 成员导入页面以导入专属请求序号与 `captureSessionIdentity()` 会话快照隔离关闭重开、换号、退出和过期响应；支部选项使用独立状态，角色字典失败不影响支部核对结果；正常 401 刷新保留文件与本次结果，由请求层重放同一次导入，不额外发送第二个 POST。仓库内 `npm run test:member-import` 用真实页面与模拟 HTTP 验证这些交互，不证明合成文件可被后端 Excel 解析。
- 后端统计当前覆盖待办与阶段分布；文件上传为本地存储。MinIO、资源中心、实时推送及完整归档均不可仅凭原计划认定可用。
