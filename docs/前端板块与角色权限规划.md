# 前端板块与角色权限规划

> 整理日期：2026-09-24
> 依据：`前端开发计划与策略.md`、`前后端待接入接口清单.md`、后端 `openapi.yaml`，以及当前前端导航、路由和权限配置。本文是目标信息架构；功能是否可开放，仍取决于后端接口、鉴权和数据范围校验。

## 1. 划分结论

Web 端规划 **8 个核心功能板块**：

1. 首页
2. 成员与支部
3. 党员发展
4. 活动与签到
5. 资讯公告
6. 资源中心
7. 数据统计
8. 个人中心

另设 **系统管理** 作为超级管理员专属的扩展板块，承载角色权限、操作日志等已有后端能力。因此，按功能域计算为“8 个核心板块 + 1 个管理员扩展板块”；按顶栏入口计算，个人中心放在头像菜单，不占顶栏。

上述划分对应策略文档第 4 章的页面计划。其中，将原文 4.6 节的“新闻、公告与下载专区”拆为“资讯公告”和“资源中心”，分别承载内容发布与文件资源管理。登录认证属于应用基础能力；党建智能助手使用全局悬浮入口；微信小程序是独立终端，均不计入 Web 端业务板块。

## 2. 按系统角色展示的菜单

| 系统角色 | 顶栏数量 | 顶栏菜单 | 头像菜单 |
| --- | ---: | --- | --- |
| 超级管理员 | 8 | 首页、成员与支部、党员发展、活动与签到、资讯公告、资源中心、数据统计、系统管理 | 个人中心、退出登录 |
| 支部管理员 | 7 | 首页、成员与支部、党员发展、活动与签到、资讯公告、资源中心、数据统计 | 个人中心、退出登录 |
| 普通成员 | 5 | 首页、我的培养、活动与签到、资讯公告、资源中心 | 个人中心、退出登录 |

普通成员菜单中的“我的培养”对应同一党员发展业务域，但只展示本人数据和个人可执行的操作。菜单、按钮和数据范围都要按系统角色控制；后端必须再次校验权限及所属支部，不能只依赖前端隐藏入口。

**系统角色与党员发展身份必须分离。**超级管理员、支部管理员、普通成员是系统角色；入党申请人、积极分子、发展对象、预备党员、正式党员等是党员发展身份。当前前端的 `activist` 是 Mock 预览角色，后端没有对应系统角色，不应将“积极分子”长期作为独立权限角色。发展身份可用于培养流程和活动参与范围判断，但不能代替系统角色授权。

## 3. 板块与角色权限矩阵

| 板块 | 超级管理员：全院 | 支部管理员：本支部 | 普通成员：本人及可参与内容 |
| --- | --- | --- | --- |
| 首页 | 全院成员、发展阶段、活动和待办概览 | 本支部数据和待办 | 个人培养进度、活动、材料和通知 |
| 成员与支部 | 成员与支部的查询、维护、Excel 导入、批量操作 | 本支部成员查询和维护、培养联系人维护；支部资料操作按最终授权开放 | 不显示管理入口 |
| 党员发展 | 全院培养档案、身份调整、批量操作、材料和档案导出 | 本支部培养记录、材料及身份流程；直接调整还是提交审批待确认 | 查看个人档案和身份历史，提交思想汇报及本人材料 |
| 活动与签到 | 全院活动创建、编辑、发布、类型管理、签到监控及统计 | 本支部活动创建、管理、签到监控及统计 | 浏览可参与活动、报名、扫码签到、查看个人记录 |
| 资讯公告 | 阅读及新闻、公告发布管理 | 阅读；是否允许发布待单独授权 | 阅读新闻和公告 |
| 资源中心 | 全局资源上传、管理和下载 | 按支部权限上传、管理和下载 | 浏览和下载有权限的资源 |
| 数据统计 | 全院及各支部统计、筛选和导出 | 本支部统计、筛选和导出 | 不设独立统计入口；个人数据放首页和“我的培养” |
| 个人中心 | 查看和编辑本人允许修改的资料 | 查看和编辑本人允许修改的资料 | 查看个人资料、培养档案、活动记录；编辑手机号、邮箱、头像等允许修改的字段 |
| 系统管理（扩展） | 角色权限、操作日志及相应基础配置 | 不显示 | 不显示 |

个人中心的姓名、学号、学院、班级等认证来源字段应只读；党员发展身份只能通过专门的身份调整流程变更。身份历史和签到记录不提供删除入口。批量操作、身份调整、支部调整及日志清理等操作应二次确认。

## 4. 与当前前端的对比

| 项目 | 当前实现 | 目标调整 |
| --- | --- | --- |
| 顶栏 | 超级管理员和支部管理员均显示首页、成员管理、党员发展、活动中心、数据统计、下载专区，共 6 项；普通成员显示首页、活动中心、下载专区，共 3 项 | 分角色显示第 2 节的 8／7／5 项；将“成员管理”扩为“成员与支部”，将“活动中心”明确为“活动与签到” |
| 资讯公告 | 新闻、公告已有列表与详情路由，但没有顶栏入口，主要从首页进入 | 增设“资讯公告”入口，并按权限区分阅读和发布管理 |
| 个人中心 | 用户下拉菜单主要显示身份、开发预览切换和退出登录 | 加入个人中心，集中展示本人资料与个人业务记录 |
| 系统管理 | 没有独立页面和菜单 | 为超级管理员规划角色权限、操作日志等页面 |
| 支部管理员权限 | 前端菜单与超级管理员相同，但成员页实际仅允许超级管理员操作 | 按本支部业务权限设计入口；待服务端接口和范围校验落实后开放操作 |
| 普通成员的培养业务 | 党员发展管理路由需要管理权限，普通成员无法进入；首页有“培养档案”等快捷入口文案 | 提供“我的培养”页面和可用的个人操作入口 |
| 接口接入 | 认证及部分超级管理员成员接口已接入；新闻、活动、党员发展、资源和业务统计等仍有 Mock 页面 | 按接口成熟度逐步接入，避免将页面存在等同于完整业务可用 |

当前导航以 `src/stores/app.ts` 为准，路由入口与权限以 `src/router/index.ts`、`src/config/permissions.ts` 为准。`前后端待接入接口清单.md` 的盘点日期为 2026-09-23，其中关于成员页“待接”的部分状态已落后于现有 `src/api/members.ts` 和 `src/views/members.vue`，实施时应以当前代码再核实。

## 5. 接口与开放条件

| 能力 | 当前契约情况 | 菜单或操作开放条件 |
| --- | --- | --- |
| 超级管理员成员与支部管理 | `/api/v4/admin/users/**`、`/api/v4/admin/branches/**` 已有接口；前端成员模块已接入其中一部分 | 完成页面与接口映射，并按超级管理员权限开放 |
| 支部管理员成员、支部和活动管理 | 现有 `/api/v4/admin/**` 仅限超级管理员；`/api/v2/branch/**` 缺少可靠的当前支部范围限制 | 补齐支部范围校验及对应管理接口后，再开放具体按钮 |
| 新闻、公告和已发布活动浏览 | `/api/v2/content/**` 已有查询接口 | 完成字段映射和页面接入；注意这些接口仍要求登录 |
| 新闻、公告发布管理 | 超级管理员管理接口已存在 | 建立后台页面并完成状态、字段和权限适配 |
| 党员发展及电子培养档案 | 现有表与 Mapper，但缺完整的身份流转、培养记录和档案聚合接口 | 后端明确身份字典、流转规则、审批规则及数据范围后开放完整流程 |
| 活动报名、二维码签到和记录 | 报名、签到及服务端限时二维码接口尚缺 | 完成服务端签发、校验、防重放和记录接口后开放正式签到 |
| 资源中心 | 资源元数据和文件服务接口尚缺 | 完成上传、下载、权限及计数接口后替换 Mock |
| 数据统计 | 业务聚合与导出接口尚缺 | 按全院／支部数据范围提供统计接口后替换 Mock |
| 系统管理 | 角色权限、操作日志接口已有 | 建立仅限超级管理员的页面；日志服务依赖后端运行配置 |

菜单可以用于说明目标结构，但在接口、鉴权或数据范围尚未完成时，不应把对应操作呈现为已经可用。特别是支部管理员不能直接复用仅允许超级管理员调用的 `/api/v4/admin/**` 接口。

## 6. 实施前需要确认的规则

1. 支部管理员调整党员发展身份，是直接生效还是提交审批；审批人和可操作的发展阶段分别是什么。
2. 支部管理员是否可以发布新闻、公告，以及能管理全院内容还是仅管理本支部内容。
3. 支部管理员能否创建、编辑支部资料；现有支部接口的服务端数据范围如何限制。
4. 活动报名是否属于一期范围；不报名的活动如何确定参与名单。
5. 党员发展身份的完整字典、允许的流转关系，以及活动参与范围如何使用身份条件。
6. 正式环境的学校统一身份认证与现有账号密码、邮箱验证码接口如何并存。
