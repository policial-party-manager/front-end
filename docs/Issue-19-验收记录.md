## 查询与导出契约及反例

| 模式 | 真实端点（省略 /api） | 前端开放条件 | 状态与导出 |
| --- | --- | --- | --- |
| 普通管理查询 | `GET /v4/admin/users/page` | 关键词或支部单独查询，可搭配状态；不发送政治身份参数 | 不传 status 是全部状态；此模式禁用导出，用户必须显式切换并确认新范围。后端另支持 roleId，当前页面原本没有该筛选入口，本次不新增。 |
| 政治身份查询 | `GET /v4/members/page` | identityId 与明确的 status；关键词输入和支部下拉禁用 | 显式传 1 或 2，不提供“全部状态”。后端不传 status 默认 1，不能理解为全部。 |
| 导出 | `GET /v4/members/export`，Blob | 只用身份模式已应用的 identityId/status 快照，无 page/size | 全部匹配记录，非当前页；未提交的下拉值不影响导出。不静默删条件或扩大范围。 |

切换模式清理不兼容条件、清空选择、回到第一页并提示。总数直接使用服务端 total，不在客户端过滤当前页、拼凑分页或全量抓取。

两处源码级最小反例（未操作数据库）：

1. `ScopedMemberServiceImpl.filterDetailIds`：设用户 101 的 username 为 `probe`、identityId=3、college=A；调用 keyword=`probe`、identityId=4。详情查询排除 101，但后续用户名查询命中，且 branchId=null，执行 `ids.add(101)`，因此身份不匹配的用户仍进入分页和导出。college/grade/major 同理。此次仅开放不含 keyword 的身份查询。
2. `AdminUserServiceImpl.pageUsers`：设用户 101 属于支部 1、username=`probe`，调用 keyword=`probe`、branchId=2。详情条件排除 101，后续用户名查询直接 `candidateIds.addAll(...)`，没有再次校验支部。此次拦截关键词与支部组合，保留各自独立能力；不偷偷忽略其中一个条件。

解除阻塞的最小后端行动：对用户名命中的候选用户继续应用全部详情条件，或将候选集合与详情范围取交集；补上述反例的服务测试，再在前端开放组合。此次未修改后端代码、SQL、配置或数据库。

新分页的 `buildVos` 只填 branchId/identityId，不补支部名称、角色及 identityName。前端使用身份字典补可查到的身份名，缺少名称时准确提示；角色缺失显示“—”。详情和编辑仍走完整管理员详情接口，不根据身份字典 roleId 推导权限。

导出后端列仅为：学号、姓名、手机号、邮箱、学院、年级、专业、班级、备注。不声称包含政治身份或支部列。现有请求层拒绝 JSON MIME 错误 Blob；页面另检查 ZIP 文件头，防止误标二进制的 JSON/HTML 错误页下载为 xlsx；未重写全局请求层。

## 批量、权限和异步约束

- 接入 `POST /v4/admin/users/batch/status`（ids/status=1或2）及 `/branch`（ids/branchId）。仅当前页选择，翻页、查询、模式切换、列表回读及会话变化清空选择。支持每页 200 条；单次去重后 1–200，不自动拆批。
- 确认展示人数、动作和支部全名。登录契约不提供本人 ID，无法可靠判断选中行是否本人，因此所有批量确认均明确提示“如选择包含当前登录账号，可能影响本人会话”。
- BatchResult 独立于 ImportResult，严格校验总数、成功失败计数、错误 ID 归属及唯一性、错误明细数量；按成员 ID 和可用姓名展示，不能显示为 Excel 行号。区分全成功、部分成功、全失败和异常响应。
- 已生效项目不会整体回滚。网络故障、超时不自动重传，提示可能已有写入；回读失败保留独立结果报告。后端是否已提交不能由浏览器错误推断。
- 支部来自正常选项，禁止 null 和伪造 ID。后端批量服务未显式检查目标支部存在及状态，前端选择约束不能替代服务端校验。
- 页面限真实登录超管；每次写入、导出及 await 后均核对权限和会话。表单、详情、选项、列表用序号隔离；保存先同步加锁再 await 校验，批量先加锁再确认；关闭、换号、卸载使旧回调失效。
- 正常 401 刷新交给请求层单次重放，页面会话身份不变；角色改变则使页面操作失效。跨标签页和同角色换号清理旧表单、选择与报告；旧导出不下载。
